# Setup and configuration

## Host prerequisites

- Linux or WSL2 with Docker Engine and Compose v2
- Node.js 24 and pnpm 11
- Python 3.12.13 and uv
- Gitleaks 8.30 (included in the devcontainer)
- At least 8 GiB RAM for core; 12 GiB is recommended for OCR
- Optional NVIDIA container runtime for the GPU profile

Run `uv run ehrfs preflight --json` for a read-only hardware report.

## Core profile

```bash
cp .env.example .env
make install
make up
docker compose -f infra/compose/compose.yaml ps
```

`make keys` is part of `make up` and creates `.local/keys` only when the keypair is missing. The
private key is ignored, mounted read-only, and never generated by the application outside demo
mode. The deterministic seed is idempotent.

## Local development

Start PostgreSQL and MinIO with Compose, then run processes independently:

```bash
make api
make worker
make web
```

Regenerate a changed HTTP contract with `make openapi`. A clean build fails if the checked-in JSON
or TypeScript schema drifts.

## OCR profiles

`make up-ocr-cpu` builds the Python 3.12 OCR boundary. Model weights are downloaded lazily to the
`ocr-models` Docker volume on first inference; core never downloads them. `make ocr-smoke` checks
the fixture checksum, service response, French text, evidence boxes, confidence, and bounded
allergy candidate.

`make up-ocr-gpu` uses the separately locked official CUDA 11.8 Paddle wheel. The NVIDIA runtime
must be installed and `nvidia-smi` must work inside Docker. CPU and GPU expose the same contract.
If `nvidia-smi` works on the host but container creation reports a missing path under
`/usr/lib/wsl/drivers`, regenerate the NVIDIA CDI configuration after the WSL driver update before
rerunning `make ocr-smoke-gpu`; the repository deliberately does not alter host CDI files.

## Database and object storage

The initialization SQL creates owner, migrator, application, worker, and read-only roles. For a
real deployment, replace local passwords, require TLS, scope MinIO credentials per process, and
run migrations as the migrator role before starting application processes.

Buckets enable versioning. Raw, documents, mapping releases, and research releases are separate;
evidence URLs expire quickly and each request creates an audit event.

## Teardown and cleanup

`make down` preserves volumes. `make clean-preview` prints the only generated host paths that the
cleanup target can remove. Review that output, then use
`CONFIRM=clean-generated make clean-confirm`. Volume deletion is intentionally not automated.
