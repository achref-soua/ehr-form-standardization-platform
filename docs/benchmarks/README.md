## 100-million-event streaming run

The harness uses 50,000-event work units, retains only bounded state, measures process peak RSS,
checks deterministic output, and rejects duplicate publication. The reviewed machine-specific
result is generated by `scripts/benchmark_100m.py`; it must not be replaced by an extrapolation
from a smaller run.

### Measured result, 2026-08-30

- Host: 12th Gen Intel Core i7-12700H, 20 logical CPUs, 15 GiB RAM, WSL2 Linux 6.6.87.2.
- Runtime: Python 3.12.13, NumPy 2.2.6, PyArrow 23.0.1.
- Shape: 100,000,000 events in 2,000 sequential 50,000-event Parquet work units.
- Elapsed: 21.087068 seconds; throughput: 4,742,242.94 events/second.
- Peak worker RSS: 91,574,272 bytes (87.33 MiB), below the 4 GiB limit.
- Published events: 50,000,001; duplicate publications: 0.
- Canonical Parquet checksum:
  `4cd0e19943e91bee5dab65cb0bb4dabadeb1e349983b11adc9f490178af2b8f6`.
- Deterministic first-partition serialization: verified.

Command: `make benchmark-100m`. The complete measured JSON is written to
`artifacts/benchmarks/answer-events-100m.json`.
